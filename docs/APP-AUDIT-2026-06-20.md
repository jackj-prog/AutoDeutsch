# AutoDeutsch — Clean-sweep app audit (2026-06-20)

Read-only audit of structure + visuals. No app behaviour was changed. Method: direct review of ~16
committed screenshots, a code-level read of `index.html` / `service-worker.js` / `build-static.mjs` /
`manifest.json` and the newest (un-screenshotted) Scenarios/mission render, plus four parallel deep-dive
passes (architecture, data-wiring, content-quality, a11y/robustness/PWA).

**Headline:** this is a high-quality, conscientious codebase. The SRS engine, persistence layer, and
content are production-grade; the real gaps are concentrated in (a) a few WCAG-AA contrast/focus issues,
(b) the maintainability cost of a 5,900-line single component, and (c) PWA polish. **Two alarming-looking
things turned out to be stale-screenshot illusions, not bugs** (see §0).

> **Snapshot note (added at deploy):** this audit was taken at `main` 33e47fc. **Immediately after**, the
> app.jsx owner shipped P5 (narrative intake → placement test → result, v2026.06.20.11) and wired the
> confusion-pair drill + exam mode (v2026.06.20.12). So the audit's "onboarding is a config modal" (§1.3),
> "P5 ready to build", and "CONFUSIONS/EXAM/PLACEMENT unwired" (§3) notes are **now superseded** — those are
> built. Everything else (a11y, the date bug, the verb-30 cap, PWA/manifest, maintainability) is unaffected
> and still open. The three newly-wired screens were not part of this audit pass and should get their own
> visual/a11y review next.

## 1. Visual / UX review (direct, from screenshots + code)

### 1.1 Strengths
- **Coherent identity.** Dark theme (`#0A0A0A`) with a German-flag accent system (black / red `#DD0000` /
  gold `#FFCC00`); the thin red→gold rule on cards, the gold focal CTA, and the radial top-glow give a
  confident, consistent look across every screen.
- **Dialogue (Listening) screen is excellent** (app.jsx:5564). Messaging-app chat bubbles (speaker
  alternation, gold/grey, tap-to-hear-and-reveal, listen-first toggle, "Play all"). The newest relocation
  scenes render through this and look great.
- **Strong Home focal hierarchy.** A single gold hero ("Review N words" / "Production practice") outranks
  everything; weak-spots, next-topic, and custom-session are clearly secondary.
- **Library curation** (`library.png`): 36 topics grouped into 5 named super-groups (Everyday Life / Out &
  About / Work & Engineering / Life Admin / Language & Society) with per-topic counts — genuinely browsable.
- **Browse** (`browse.png`): article-aware A–Z (der Abend files under A), sticky letter headers, per-row
  audio + Known. The **umlaut helper row (ä ö ü ß Ä Ö Ü)** above typed inputs is a thoughtful touch for
  German entry (`drill.png`, `d_cloze.png`).
- **Populated Progress** (`r_stats_adv.png`): the P2 "what you can do" lead + memory-strength stage bars +
  drill coverage, with the database panels demoted under "Under the hood" — information-dense but well-ordered.

### 1.2 Visual findings
- **[Low] Session-canvas vertical rhythm varies by state.** Recall-revealed centers the card; the recall
  *verdict* sits low with a void above; production-answered is top-anchored with a void below; typed is
  top-anchored (keyboard space). Most of this is intentional per state, but the empty regions read
  inconsistently. Consider a single vertical-centering rule for non-typed states.
- **[Low] Production answered state is information-dense.** `prod_answered.png` stacks verdict +
  capitalisation note + recall time + production streak + attempts + memory level + last-seen + 3 actions
  (Why?/Show hint/Show example) — ~9 elements. Correct and color-restrained, but a candidate for progressive
  disclosure (show the verdict + next-review; tuck the rest behind a "details" affordance).
- **[Low/copy] Settings status copy** reads "Open one cache to cache" (`settings.png`) — awkward/garbled;
  reword (e.g. "Open the app once while online to cache for offline").

### 1.3 Product/UX observations (not bugs)
- **[Med] Onboarding is a 3-field config modal** (`onboarding.png`: level / daily target / practice style).
  This is exactly the "tool frame" the roadmap critiques — and the **P5 placement data + scoring + build
  spec are already shipped and `⬜ ready to build`** (`docs/P5-placement-buildspec.md`) to replace it with a
  narrative intake + 2-min placement. High-leverage next app.jsx task.
- **[Med] AI Tutor requires the user's own Anthropic API key** (`settings.png`, Home "setup needed" card).
  A real adoption barrier for a consumer app; already deferred in the roadmap (productize later behind a
  hosted proxy). Fine as-is, worth keeping visible as a launch blocker for that feature.

## 2. Architecture & code health
The module-scope layer (≈50 pure helpers, memoized `Icon`/`Btn`/`ProgBar`, `RootErrorBoundary`) is genuinely
well-factored. The cost is concentrated in **`App()` itself: one ~4,840-line component** holding ~80 `useState`
slots and all 15 screens as inline `screen === "…"` gates.

- **[High] State over-centralization** — ~80 `useState` across unrelated domains (session, SRS, tutor, audio,
  reminders, onboarding, celebrations) in one component (app.jsx:1066–1284). Extract custom hooks
  (`useProgress`, `useDailyStreak`, `useAudioMode`, `useTutor`, `useReminders`).
- **[High] Triplicated review-launch logic** — `startWeakReview` (2722), `startDueReview` (2748),
  `startAlmostReview` (2772) copy-paste the same ~11-line setMode/setCategory/setScreen ladder verbatim. Any
  new mode must be edited in 3+ places. Collapse to one `launchReview(buckets, cap, label)` + a shared
  `routeForMode(mode)`.
- **[Med] Real latent date bug** — `new Date("YYYY-MM-DD").getTime()` (trend-prune at 1760 & 2166) parses as
  **UTC midnight**, while `todayKey` builds keys from **local** date (504–509). In negative-UTC-offset zones
  the 60-day cutoff can be off by a day. Reuse the existing local `parseDay` helper.
- **[Med] Triplicated constants** — `LEVEL_TITLES` (554 / local 4204 / local 4852) and `LEVEL_COLOR`
  (555 / 4203 / 4800) defined 3× each; the journey/CEFR math is recomputed in home (4205–4209) and stats
  (4853–4859). Use the module constants + `deepStats`.
- **[Med] Schema forward-compat gap** — import enforces `schemaVersion === "v7"` (1715), but the primary
  `gfc-v7` blob has no version field/check on normal load (1340). Embed + check a version on the main blob.
- **[Low] `cardsLenRef.current = …` assigned during render** (3307) — works, but a render side-effect smell.
- **Done well (praise):** the Leitner engine guards against same-day cram inflation (`nextBox`, 38);
  `normalizeEntry` is a real schema-migration layer; localStorage is uniformly try/catch + write-probe +
  daily backup/restore + debounced flush-on-unload; leech definition is consistent; `checkMatch` grading is
  careful (capitalisation/ß flagged not silently accepted; typo tolerance gated to len ≥ 5); broad
  `useMemo`/`React.memo` coverage.

**Top 5 refactors (no rewrite needed — seams exist):** (1) split the 15 screens into a `screen→component`
map; (2) de-dup the 3 review launchers; (3) extract state into custom hooks; (4) collapse the triplicated
level constants + journey math; (5) fix the UTC/local date mismatch.

## 3. Data ↔ UI wiring & completeness
- **Word/level counts: fully dynamic and correct** (see §0). No fixed-count assumption would crash or hide
  content as the library grows. ✅
- **[Low–Med] One real fixed-number cap:** the verb-session size is hardcoded to **30** (app.jsx:2444 & 3462,
  `cat === "__verb__" ? 30 : …`) while every other mode derives its ceiling dynamically. With `VERBS` now at
  **92**, a verb session can never exceed 30 cards (all 92 *can* still appear via weighted draw — it only
  caps session length). Change `30` → `VERBS.length`.
- **`CONFUSIONS` / `EXAM` / `PLACEMENT` are unwired** (0 references in app.jsx) — **expected**: data shipped to
  the bundle, UI pending. No dead/dangling reference (`capability.exam` is a separate telc-readiness heuristic,
  not the `EXAM` bank). These are the three `⬜ ready to build` app.jsx tasks.
- **All missions + dialogues are reachable.** Scenarios → mission → dialogues is fully data-driven; all 14
  newly-added missions and their dialogue titles resolve against `DIALOGUES`. ✅

## 5. Accessibility, robustness, PWA
Strong baseline: icons are `aria-hidden` + every icon-button has an `aria-label`; `:focus-visible` outlines
exist for buttons (not just inputs); broad keyboard support + `aria-live` feedback + `role="dialog"` modals;
reduced-motion gates nearly every animation; localStorage/JSON.parse uniformly try/catch; Web Speech &
SpeechSynthesis fully feature-detected with an iOS shadowing fallback; SW precaches the shell + React CDN +
font CSS with lockstep app-shell updates and one-shot reload-loop protection.

Findings:
- **[Med] Contrast — disabled CEFR rows at `opacity:0.45`** composite to ~**1.95:1** (app.jsx:4934) — clear
  AA failure. Raise to ≥0.7 / lighten.
- **[Med] Contrast — red `#DD0000` as small text** ~**3.84:1** (412, 3377, 5142…) fails AA-normal (ok only
  when bold/large). Use `#F87171` for small red text.
- **[Med] Empty session pool → blank dead-end** (no crash). `startSession` (2546) doesn't assert
  `cards.length > 0` before `setScreen`; the render guard then shows nothing and `activeCardMissing` won't
  redirect (needs `length > 0`). Narrow path (e.g. an empty band), but unguarded — add `if (!sel.length) {…}`.
- **[Med] No focus management on screen change; modals not focus-trapped.** Focus is never moved on
  navigation; Escape closes setup/settings but not onboarding/rankUp (1785). Move focus to the screen
  container/heading; trap focus in dialogs; extend Escape.
- **[Med] Montserrat woff2 not precached + `<link>` injected late** (app.jsx:3581; SW caches only the CSS at
  service-worker.js:17). Declared in `index.html` CSS but the font is React-injected, so cold first-run-offline
  renders the system sans-serif (acceptable, not broken). Move the `<link>` to `index.html <head>` and/or
  precache the woff2.
- **[Med] `manifest.json` incomplete** — no `screenshots` / `id` / `scope` / `lang`; both icons are
  `purpose:"any maskable"` (maskable clipping risk). Add the missing fields and a dedicated padded maskable icon.
- **[Low] `(idx+1)/cards.length` → NaN if 0 cards** (5090/5229/5457, same root as the empty-pool path);
  unvalidated `ev.results[…][0]` in speech `onresult` (3033); `user-scalable=no` blocks pinch-zoom
  (index.html:5) — WCAG 1.4.4, intentional for swipe UX.

## 6. Coordination note
- **[Low] `APP_VERSION` (app.jsx:679 = "2026.06.20.10") lags the content deploys.** The seven content-only
  deploys this session correctly did **not** bump it (it lives in app.jsx, the other agent's lane) and the
  service-worker cache *does* bump from a content hash, so updates still reach devices — but the
  version label shown in Settings is stale relative to the data. Worth a convention: either move a
  `DATA_VERSION`/content-hash display into Settings, or have the app.jsx owner bump `APP_VERSION` when they
